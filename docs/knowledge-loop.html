PRD
#3
Point redemption — two rules, two different outcomes
Customers can redeem points for a discount. 1pt = 1 cent. 50% cap. Points are earned on the post-discount total. This PRD adds two rules: one lands in a clean slot, one supersedes RULE-EARN-002. validate-knowledge runs twice.
2 rules: clean + supersede

User stories proposed in this PRD

1
As a customer with sufficient points, I want to apply them as a discount at checkout so that accumulated points have tangible value.
→ RULE-REDEEM-001
2
As a customer, I want a clear error if I try to redeem more than my balance so that I can adjust the amount.
→ RULE-REDEEM-001
3
As a customer, I want redemption capped at 50% of my order total so that orders always have a minimum payment.
→ RULE-REDEEM-001
4
As a customer, I want new points earned on what I actually paid (post-discount) so that redemption does not create a compounding points loop.
→ RULE-EARN-003
5
As a customer, I want my points restored if my order fails after deduction so that I never lose points without receiving an order.
→ RULE-REDEEM-001
Two rules incoming from this PRD. validate-knowledge runs once per rule. RULE-REDEEM-001 lands in a new slot — no existing rule owns order.discount.apply. RULE-EARN-003 lands in the same slot as RULE-EARN-002 — conflict check fires, PRDs are fetched.

    introduced_prd: 3
    user_story_ref: "PRD #3 Story 1, 2, 3, 5"
    test_cases:

        expected: { discount_cents: 200 }  # within 50%

        expected: { discount_cents: 500 }  # capped at 50%

  - id: RULE-EARN-003
    status: active
    conflict_key: customer.loyaltyPoints.earn
    formula: "floor(effective_total_cents / 100) * tier_mult"

    plain_english: "Earn on post-discount total × tier multiplier"
